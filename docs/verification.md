# 실행 검증 결과

검증일: 2026-09-05, Windows / Node.js 22.23.2 / 실제 Chrome.

## 빌드와 자동 검증

- `npm.cmd run build`: TypeScript 검사 및 Vite 프로덕션 빌드 성공.
- `npm.cmd test`: 1개 파일, **21개 테스트 모두 통과**.
- 최종 프로덕션 JS 약 244.37 kB, gzip 약 77.82 kB. CSS 약 26.87 kB, gzip 약 6.60 kB.
- 3개 병기 × 3개 무공 × 4개 지역의 36조합을 각 600초 시뮬레이션하여 유효한 진행·생존·후퇴를 검증.
- 쪼갠 시간/합친 시간의 결정론적 결과, 온라인/오프라인 동일 계산, 8시간 상한, 시계 역행, 초 미만 시간 보존, 정지 상태, 4지역 해금, 강적 부재 정지, 구매 비용, 성장 비용, 기록 확인의 재지급 방지, 저장 복원·손상 입력 검증 포함.

## 실제 GUI 플레이

Playwright CLI로 사용자가 보는 버튼·선택 상자를 조작했습니다. 전체 진행 검증에서는 스탯이나 해금 값을 주입하지 않고, 앱에 제공한 `체험 · 1분 보내기`만 사용하여 대기를 줄였습니다.

1. 첫 청죽림 자동 조우와 보상·숙련 증가 확인.
2. 대숲의 늑대왕 직접 도전 → 자동 격파 → 적운산채 개방.
3. 파암일격 선택, 백목창 구입 및 장착, 호흡 단련, 해당 변경 저장 확인.
4. 적운산채·운무나루·백운고개 이동, 일반 조우 4회, 강적 도전과 격파를 반복하여 **4개 지역의 강적 모두 격파**.
5. 보상 목표를 깨달음으로 변경하고, 추천된 운무나루 대신 청죽림으로 직접 이동 가능함을 확인.
6. 누적 보고 확인 전후로 행낭에 중복 보상이 추가되지 않고 보고 구간만 초기화됨을 확인.
7. 활동 일시정지 → 재로드 → 보유 자원 동일 → 활동 재개 확인.

## 프로덕션 재접속·실패 검증

프로덕션 미리보기 `http://127.0.0.1:4173`에서 별도로 검증했습니다. 아래 항목만 테스트용 저장 표본을 주입했습니다.

- 마지막 기록을 2분 이전으로 둔 뒤 재접속: **120초 정산**, 귀환 안내 표시.
- 일시정지 후 다시 로드: 자원 동일, 중복 정산 없음.
- 손상 JSON으로 로드: 임시 게임을 계속 조작할 수 있고, 손상 원문 `{broken`이 덮어써지지 않음.
- `Storage.setItem`의 저장 공간 오류를 주입: 저장 불가 안내를 표시하고 게임은 실행됨. 주입을 제거한 뒤 정상 재로드.
- 결과: `OFFLINE_RELOAD_CORRUPTION_QUOTA_OK`, 애플리케이션 런타임 오류 **0건**.

개발 도중 포매팅에 따른 Vite 재시작과 저장 테스트가 겹쳐 개발 클라이언트 연결 오류 1건이 발생했습니다. 테스트 환경의 일시적인 재시작 영향으로 확인했으며, 최종 빌드 및 서버 재시작이 없는 프로덕션 검증으로 대체하여 통과했습니다.

## 검증의 범위

기능이 이어지는 최소 루프와 오류·데이터 일관성을 확인했습니다. 실제 사용자의 장기 재미, 밸런스, 최종 미술 선호를 검증했다는 뜻은 아닙니다. 다음 관찰 대상은 병기·무공 변경으로 체감이 달라지는지, 추천 설명이 선택을 돕는지, 누적 결과를 보고 다음 지역이 궁금해지는지입니다.
