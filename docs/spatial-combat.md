# 공간 기반 자동 전투 시제품

후속 전투장/HUD 정제: [지역별 전투장 표현 정제](combat-arena-polish.md). 아래 내용은 최초 공간 전투 구현 기록입니다.

2026-09-12 · `codex/spatial-combat`

## 선택한 공간

기존 픽셀 배경·캐릭터, `game.ts`, `useGame.ts`, `Art.tsx`, `App.tsx`, 픽셀 프레젠테이션 문서와 실제 실행 화면을 조사했습니다. 기존 표현은 백분율로 고정한 좌우 위치에서 자세만 바뀌고, 체력 0인 적을 즉시 숨기는 구조였습니다.

**작은 2.5D 지면 공간(belt-scroll)**을 선택했습니다. 순수 횡스크롤은 여러 적을 앞뒤로 구분하기 어렵고, 완전한 탑다운은 현재의 측면 스프라이트와 맞지 않습니다. 지면 위 x/y 이동과 y 깊이 정렬을 사용하면 기존 좌우 그림을 살리면서 접근·포위·타깃 전환을 표현할 수 있습니다.

전투 시 같은 지역의 풍경을 지면 중심으로 당겨 봅니다. 논리 좌표는 720×360이며 화면에는 여유 공간에 맞춰 축소됩니다. 장애물 없는 작은 전투 공간이므로 NavMesh나 길찾기는 없습니다. 기존 이미지 파일을 교체하거나 새로 생성하지 않았고 Teamfight Manager의 자산·UI·맵·코드는 사용하지 않았습니다.

## 이동과 타게팅

- 무인은 **기존 판정과 동일하게 살아 있는 첫 번째 적**을 목표로 삼습니다. 가장 가까운 적으로 임의 변경하지 않습니다.
- 상대와 멀면 접근하고, 앞뒤 높이가 크게 다르면 상대의 측면으로 돌아 공격 방향을 맞춥니다. 타격 뒤에는 잠깐 간격을 벌립니다.
- 적도 무인에게 접근합니다. 대기 중에는 서로 다른 각도의 자리를 찾아 무인을 따라 움직이고, 공격 또는 피격 차례에는 교전 거리로 접근합니다.
- 모든 좌표는 지면 범위 안으로 제한합니다. 가까운 생존자 사이에는 작은 분리 보정을 반복 적용해 동일 위치에 완전히 겹치지 않게 합니다. 공격 거리와 분리 거리는 그림을 위한 값입니다.
- 접근 중 방향, 발밑 그림자·목표 표시, 실제 위치 변화, 짧은 공격 자세와 피격 밀림/경직으로 상황을 보여 줍니다. 사망한 적은 즉시 삭제하지 않고 쓰러져 사라집니다. 무인은 다음 적을 향해 이동합니다.
- 승리 후 약 1초 동안 마무리하고 기존 탐험 장면으로 돌아옵니다. 안전 후퇴에서는 무인이 뒤로 빠지고 기존 회복 흐름으로 복귀합니다.

## 기존 판정과의 관계

`src/game.ts`, `src/game.test.ts`, `src/useGame.ts`는 변경하지 않았습니다. 기존 저장 키·형식·진행·보상·가격·성장·공격 간격·명중·회피·방어·피해·RNG·부재 정산을 유지합니다.

새 `CombatMotion`은 연속된 GameState 스냅샷을 읽는 메모리 전용 표현 모델입니다. 기존의 생존 순서, 실제 체력 차이, 승리/후퇴 결과를 접근 → 타격 → 피격으로 재생합니다. 회피와 반격의 보조 표시에는 기존 로그를 참고합니다. 가까워졌을 때 시각적 타격을 보여 주며, **좌표나 이동은 판정에 되돌려 보내지 않습니다.** 따라서 카이팅이나 사거리로 실제 공격을 취소하거나 전투 결과를 바꾸는 시스템은 아닙니다.

실제 판정과 공간 표현 사이에는 접근·타격 재생에 따른 짧은 시간차가 있습니다. 공간 전투의 적 체력은 피격 순간에 맞춰 표시하며, 보유 자원·원래 로그·상단 무인 HUD는 기존 상태를 사용합니다. 한 1초 판정에 함께 발생한 연타/반격은 짧은 한 교전 단위로 묶습니다. 범위 피해나 반격 피해를 받는 적도 거리를 확보한 후 피격시킵니다.

일시정지는 위치와 동작 시간을 함께 동결합니다. 1분 보내기, 부재 정산, 새로고침, 지역 변경 및 숨겨진 탭에서는 지난 타격을 쌓아 재생하지 않고 현재 조우로 재구성합니다. 지도에서 돌아오면 현재 전투로 다시 배치됩니다. 이 좌표는 저장 데이터에 들어가지 않습니다.

## 실행·검증

```powershell
cd D:\projects\FirstForm-Prototype
npm.cmd run dev
# http://127.0.0.1:5173
```

프로덕션: `npm.cmd run build`, `npm.cmd run preview` → `http://127.0.0.1:4173`.

- 기존 21개 + 신규 13개, **총 34개 테스트 통과**. TypeScript 검사와 프로덕션 빌드 통과.
- 입력 상태를 재귀적으로 동결한 테스트에서 표현을 갱신해도 상태가 바뀌지 않음을 확인. 프레임 표현을 구동한 90초 진행 결과와 표현 없이 계산한 결과 동일.
- 실제 3체 전투에서 무인·적 각각의 이동, 공격 거리, 경계, 완전 겹침 방지, 1→2→3 타깃, 사망, 종료를 확인.
- 검/도/창 × 무공 3개 × 지역 4개, 36조합을 각각 120초 재생해 타격 대기가 계속 쌓이지 않는지 확인.
- Chrome의 새 저장 문맥에서 탐험 → 조우 → 3체 전투 → 격파 → 탐험 복귀를 실제 녹화. 시간·개별 좌표·자세·체력을 연속 수집. 콘솔/페이지 오류 없음.
- 모바일 390×844, 320×568, 844×390, 태블릿 768×1024와 PC 1280×800에서 확인. 가로 넘침 없음. 가로 화면에서는 HUD가 적을 가리지 않게 왼쪽으로 이동.
- 실제 UI에서 무공·병기 변경, 단련, 네 강적 격파와 지역 해금, 강적 중 장착 변경 금지, 보상 목표 변경, 다른 열린 지역 선택, 일시정지·지도 복귀, 보상 기록 확인, 새로고침 저장 유지 확인.
- 보상 기록 확인 전후 자원 동일, 일시정지 후 새로고침 상태 동일. 기존 게임/저장 파일 해시와 기존 이미지 변경 여부를 별도로 확인.

실행 스크립트·원본 녹화·연속 스크린샷·좌표/검증 로그는 Git에서 제외한 `output/playwright/spatial/`에 저장했습니다. 대표 파일은 `01-exploration.png`, `02-combat.png`, `combat-motion.mp4`입니다.

## 임시 표현과 확장 지점

기존 16칸 아틀라스를 그대로 사용합니다. 적에게는 전용 걷기/피격/사망 프레임이 없으므로 실제 좌표 이동에 작은 보행 흔들림을 더하고, 피격은 밝기·밀림, 사망은 회전·축소·사라짐으로 표현합니다. 좌우 방향만 있고 전용 8방향 그림은 아닙니다. 그림마다 달랐던 발 여백은 실제 알파 픽셀 위치를 읽어 보정했습니다. 네 지역의 적/강적은 기존 공용 외형을 유지합니다.

`weaponMotion`의 reach/speed/recoil/frame은 검·도·창의 **표현 전용** 차이를 담습니다. 향후 창·극의 긴 찌르기, 권법의 짧은 진입·연속 동작, 암기의 이격·발사체를 추가할 때 이 프로필과 접근 목적지, 타격 재생 부분을 확장할 수 있습니다. 실제 사거리나 이동이 판정에 영향을 주는 변경은 별도의 밸런스 작업입니다.

장애물, 충돌 기반 공격 취소, 새로운 위치 저장, 새 병기나 수치 변경은 도입하지 않았습니다. 동작 줄이기 설정은 부가 흔들림과 전환 효과를 줄이며 전투를 이해하는 데 필요한 위치 이동은 유지합니다.
